# AI Agricultural Advisor

Feature 1 ("Agricultural Advisor") of a larger 5-feature AI Agri-Assistant academic
project, targeting France. A farmer or investor clicks a location on a map → the
system resolves the exact cadastral parcel → pulls real soil, weather, and satellite
data for that specific parcel → scores crop suitability → retrieves grounded
agronomic advice via RAG → generates a French-language report, with explicit
safeguards against the LLM inventing numbers not present in the source data.

Built as a standalone service (unified FastAPI backend + static frontend, no
separate frontend server) that can later plug into the shared 5-feature platform.
Every external data source is free / no-key, per the project's academic constraint.

---

## 1. What it does

1. **Parcel resolution** — a map click resolves to an exact cadastral/RPG parcel
   boundary (polygon), with an agricultural-status check and neighboring-parcel
   crop context.
2. **Data fetch** (parallel) — soil (SoilGrids), weather (Open-Meteo 16-day
   forecast), satellite NDVI (Sentinel-2 via Copernicus), and a DL-based
   "what's actually growing here right now" classification (Phase B, see §7).
3. **Crop suitability scoring** — a rule-based scorer (documented placeholder for
   a future trained model) across 5 crops: `ble_tendre`, `mais`, `colza`, `orge`,
   `tournesol`. Uses pH, temperature, nitrogen, CEC, precipitation, and soil
   workability (bulk density + coarse fragments).
4. **RAG retrieval** — Chroma + Mistral embeddings, per-crop document corpus
   ingested from HAL (INRAE's open repository), filtered by the top-scoring crop.
5. **Two-stage report generation** — Stage 1 (Mistral) extracts grounded claims
   from retrieved chunks and flags data gaps; Stage 2 (Mistral) writes the
   French-language markdown report. Soil/weather/vegetation/DL summaries are
   **never** generated by the LLM — they're built directly from the real fetched
   data in Python, so there's no path for the model to invent a figure for them.
6. **Grounding defense** (three layers): claims citing a fabricated source chunk
   are dropped; the Stage 2 prompt forbids introducing new numbers; a
   post-generation numeric audit parses every number in the report to a real
   float and cross-checks it against the source data (tolerant of French
   comma-decimals vs JSON period-decimals) — anything unverifiable is flagged
   in the report's "unverified_figures".

## 2. Requirements

- Python 3.11+ (project developed/tested on Windows with 3.13; if you hit a
  package with no wheel for your Python version, see §2.2)
- Free accounts, no payment required:
  - [console.mistral.ai](https://console.mistral.ai) — Mistral API key (LLM +
    embeddings)
  - [dataspace.copernicus.eu](https://dataspace.copernicus.eu) — OAuth client
    (`User Settings → OAuth clients`) for satellite data
- All other data sources (SoilGrids, Open-Meteo, French cadastre/RPG, HAL) need
  no signup or key.

### 2.1 Install

```bash
python -m venv venv
venv\Scripts\activate      # Windows
# source venv/bin/activate # macOS/Linux

pip install -r requirements.txt
```

### 2.2 If a pinned version fails to install

`requirements.txt` pins exact versions for reproducibility, but a pin can fail
if your Python version has no matching wheel (this happened with `torch==2.4.1`
on Python 3.13 — no wheel existed yet, fixed by bumping to `2.6.0`). If you hit
this on a newer Python than the project was pinned against, install that one
package unpinned (`pip install torch`) and update the pin in `requirements.txt`
to whatever version actually installed.

### 2.3 Configure `.env`

Copy the keys below into a `.env` file in the project root (see `config.py` for
every available setting — everything not listed here has a working free-tier
default and doesn't need to be touched):

```
MISTRAL_API_KEY=your_key_here
COPERNICUS_CLIENT_ID=your_client_id_here
COPERNICUS_CLIENT_SECRET=your_client_secret_here
```

**Do not commit or share `.env`** — it holds live credentials.

## 3. Running the server

```bash
uvicorn main:app --reload
```

Open `http://127.0.0.1:8000` for the map UI, or use the API directly:

| Route | Method | Purpose |
|---|---|---|
| `/` | GET | Serves the Leaflet map frontend |
| `/parcel/resolve` | POST | Resolve a map click to a parcel (cadastre → RPG → manual fallback) |
| `/parcel/neighbors` | POST | Crop-distribution context from nearby RPG parcels |
| `/advise` | POST | Full pipeline — returns the complete `AdvisorReport` |
| `/health` | GET | Basic health check |

`/parcel/resolve` and `/advise` both expect a body like:
```json
{"point": {"lat": 48.4520, "lon": 1.4925}}
```

## 4. Fetching and ingesting the RAG corpus

The advisor can't give grounded agronomic advice without a document corpus
behind it. Documents come from HAL (France's open institutional repository,
INRAE's collection in particular) and are ingested per crop.

### 4.1 Fetch documents for one crop

```bash
python scripts/fetch_hal_documents.py --query "ble tendre fertilisation" --coll INRAE --rows 30 --out ./corpus_ble
```

- `--query` (required) — search terms, e.g. `"maïs irrigation rendement"`
- `--coll` — restrict to a HAL collection code (`INRAE` recommended for
  agronomic quality); omit to search all of HAL
- `--rows` — max records to fetch (default 30)
- `--out` — output folder for downloaded PDFs (default `./corpus`)

Repeat per crop, into separate folders — **don't mix crops in one folder**, the
ingestion step below tags every chunk in a folder with a single `--crop` value:

```bash
python scripts/fetch_hal_documents.py --query "maïs irrigation rendement" --coll INRAE --out ./corpus_mais
python scripts/fetch_hal_documents.py --query "colza fertilisation azote" --coll INRAE --out ./corpus_colza
python scripts/fetch_hal_documents.py --query "orge culture pratiques" --coll INRAE --out ./corpus_orge
python scripts/fetch_hal_documents.py --query "tournesol culture irrigation" --coll INRAE --out ./corpus_tournesol
```

### 4.2 Ingest into Chroma

```bash
python scripts/ingest_rag_corpus.py --input ./corpus_ble --crop ble_tendre
```

- `--input` (required) — folder of PDFs to ingest
- `--crop` — tags every chunk with this crop (normalized through
  `taxonomy.py`, so `ble`, `blé`, `BTH`, etc. all resolve consistently) — leave
  empty for crop-agnostic documents
- `--region` / `--topic` — optional extra metadata tags for filtered retrieval
- `--max-size-mb` — skip oversized PDFs (default set in the script; guards
  against `pdfminer` hangs on huge scanned documents)
- `--force` — re-index a file even if it's already in the store (default:
  already-indexed files are skipped, so re-running ingestion is idempotent —
  this guards against the duplicate-chunk issue `dedupe_chroma.py` exists to
  clean up, see §5)

Repeat for each crop folder. Documents are chunked structure-aware (headings/
sections, not blind character counts), embedded with Mistral Embed (falling
back to a local multilingual model if no API key / quota is hit), and stored
in `chroma_store/` with crop/region/topic metadata for filtered retrieval.

## 5. Testing & debugging utilities

Small standalone scripts, each runnable directly with `python <script>.py` —
none of them need the server running unless noted. Useful when something in
the pipeline misbehaves and you want to isolate which layer is at fault.

| Script | What it checks |
|---|---|
| `check_rpg.py` | Raw RPG WFS point query for a known coordinate |
| `check_rpg_layers.py` | Lists available RPG/parcel layer names on the WFS endpoint (useful if a layer name ever changes upstream) |
| `check_rpg_raw.py` | Raw WFS capabilities response, for debugging "layer not found" issues |
| `check_cadastre_fields.py` | Prints every property key on a raw cadastre API response (useful after any IGN API schema change) |
| `check_parcel.py` | End-to-end `resolve_parcel()` call, prints source/parcel_id/warning |
| `check_retrieve.py` | Sanity-checks `rag_service.retrieve()` against the populated corpus, without going through `/advise`. Usage: `python check_retrieve.py --query "fertilisation azote ble" --crop ble_tendre` |
| `check_chroma.py` | Prints total chunk count and a sample peek from the Chroma collection |
| `check_satellite.py` | Full Copernicus verification: token fetch → raw Statistics API JSON → parsed `VegetationData` — prints the raw JSON *before* the parsed result so shape mismatches are visible directly |
| `dedupe_chroma.py` | Removes exact-duplicate chunks (same source doc + text) that accumulated from pre-idempotent ingestion runs. Dry run by default; add `--apply` to actually delete |
| `test_advise_e2e.py` | Full pipeline smoke test against a **running server** — resolves a parcel, checks neighbors, calls `/advise`, and validates the report has all expected sections with zero unverified figures. **Run this after any change touching `main.py`, `synthesis_service.py`, or the services** |

### Running the end-to-end test

```bash
# terminal 1
uvicorn main:app --reload

# terminal 2
pip install httpx   # if not already installed
python test_advise_e2e.py
```

Edit the `COORD` constant at the top of the script to point at a parcel you
know is RPG-registered with a declared crop, if you want the
declared-vs-observed DL mismatch path actually exercised.

## 6. Known limitations (not yet fully solved)

- No manual boundary-drawing UI fallback for unregistered parcels (Section
  8.1 of the original plan) — currently shows a warning and stops.
- No fertilizer-dose or irrigation-schedule calculator (needs real agronomic
  formulas, e.g. the French *balance azotée* method — not something an LLM
  should estimate).
- No yield prediction (needs the DL layer + historical data first).
- Citation readability — some claims cite raw chunk UUIDs rather than
  resolving to a readable source document name.
- `/parcel/neighbors` crop percentages are count-based, not area-weighted.
- No clean JSON-only endpoint yet for the other 4 platform features
  (Government Regulations, Business Advisor, etc.) to integrate against.

## 7. Phase B — DL satellite classifier (optional, in progress)

Separate from the core 5-crop recommendation engine. Adds a "what does the
satellite currently see growing here" field to the report (descriptive
context, like NDVI — **never** fed into crop scoring).

- Model: TempCNN, pretrained on [BreizhCrops](https://github.com/dl4sits/breizhcrops)
  (RPG-labeled Sentinel-2 time series, Brittany, France), fine-tuned on its
  native 9-class taxonomy (barley, wheat, rapeseed, corn, sunflower, orchards,
  nuts, permanent meadows, temporary meadows).
- Fine-tuning: `finetune_dl_service.py --datapath ./breizhcrops_dataset --epochs 8`
  (recommend a GPU — Colab free tier works; CPU works but is considerably
  slower, expect hours not minutes for a full run).
- **Checkpoint placement**: drop the resulting `tempcnn_finetuned.pth` into
  `dl_checkpoints/` in the project root (matches `config.py`'s
  `DL_CHECKPOINT_PATH` default). Without it, `dl_service.py` degrades
  gracefully — the DL bullet is simply omitted from the report, no crash.
- If the RPG-declared crop and the DL prediction disagree, the report adds a
  one-line flag under "Alertes" — can indicate a stale RPG declaration, a
  parcel mid-rotation, fallow land, or a change of operator.

## 8. Project structure

```
main.py                        FastAPI orchestrator — routes
config.py                      Central settings (env-driven)
schemas.py                     All Pydantic models
taxonomy.py                    RPG crop-code <-> internal key <-> French display name

services/
  parcel_service.py            Cadastre + RPG resolution, neighbor crop context
  soil_service.py               SoilGrids
  weather_service.py            Open-Meteo
  satellite_service.py          NDVI (Sentinel-2 L2A) + raw band time series (L1C, for Phase B)
  ml_service.py                 Rule-based crop suitability scoring
  rag_service.py                Chroma retrieval (crop/region/topic filtered)
  synthesis_service.py          Two-stage Mistral synthesis + grounding audit
  dl_service.py                 Phase B: checkpoint-based crop classification

scripts/
  fetch_hal_documents.py        Pull PDFs from HAL for a given query
  ingest_rag_corpus.py          Chunk, embed, and store PDFs into Chroma

static/index.html               Leaflet map frontend

dl_checkpoints/                 Fine-tuned model checkpoint goes here (see §7)
chroma_store/                   Persisted vector DB
corpus_<crop>/                  Downloaded HAL PDFs, per crop (created by §4.1)
```

## 9. Quick start, end to end

```bash
# 1. Install
python -m venv venv && venv\Scripts\activate
pip install -r requirements.txt

# 2. Configure .env with MISTRAL_API_KEY, COPERNICUS_CLIENT_ID, COPERNICUS_CLIENT_SECRET

# 3. Build the RAG corpus (repeat per crop — see §4)
python scripts/fetch_hal_documents.py --query "ble tendre fertilisation" --coll INRAE --out ./corpus_ble
python scripts/ingest_rag_corpus.py --input ./corpus_ble --crop ble_tendre
# ...repeat for mais, colza, orge, tournesol

# 4. (Optional) Phase B — drop a fine-tuned checkpoint into dl_checkpoints/

# 5. Run
uvicorn main:app --reload

# 6. Verify
python test_advise_e2e.py
```
